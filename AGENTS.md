# Documentation audience

Keep the root README user-facing: what visitors can find on the website, links to public pages, language support, the mobile/desktop apps and help.

Put architecture, local setup, commands, tests, deployment instructions and development history in `docs/DEVELOPMENT.md` or specialized files under `docs/`. The root README may contain a clearly labeled link to developer documentation, but should not reproduce those instructions.

Keep preview URLs and old branch names in dated developer notes rather than using them as the main user entry point. Check actual publication status before describing a feature as available.
